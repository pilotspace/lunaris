# Migrating 0.5 → 0.6: llama.cpp-only inference (N-03 reversal)

v0.6 deletes the candle inference stack and makes
[`lunaris-llamacpp`](../../crates/lunaris-llamacpp) the only local
embed/rerank runtime. The extractor and verifier LLM slots become
**remote-only**. This reverses the v0.4 N-03 candle-only cutover
([`0.3-to-0.4-native-default.md`](0.3-to-0.4-native-default.md)); the
rationale and gate numbers live in the
[cutover ADR](../decisions/2026-07-10-llamacpp-only-cutover.md).

## TL;DR table

| v0.5 (candle) | v0.6 (llama.cpp) |
|---|---|
| `lunaris-embed-native::NativeEmbedder` (FP16 safetensors) | `lunaris_llamacpp::LlamaCppEmbedder` (Q4_K_M GGUF) |
| `lunaris-rerank-native::NativeReranker` (FP32) | `lunaris_llamacpp::LlamaCppReranker` (Q5_K_M GGUF) |
| features `native` / `embedder-gguf` / `reranker-gguf` | feature `llamacpp` (**default on the umbrella**) |
| features `cpu-accelerate` / `cpu-mkl` / `cuda-fa2` | gone — llama.cpp picks CPU kernels itself |
| features `metal` / `cuda` | `metal` / `cuda` / `vulkan` (forward to llama-cpp-2) |
| candle Gemma-3 extractor/verifier (`candle` feature) | remote-only: `LUNARIS_EXTRACT_PROVIDER` / `LUNARIS_VERIFY_PROVIDER` |
| weights in `~/.cache/lunaris/models/<repo>/` (safetensors) | GGUFs in `~/.lunaris/models/` (tokenizer.json still read from the legacy cache dir for token counting) |
| `EmbedderConfig.native()` / `.native_quantized()` | `EmbedderConfig.llamacpp(gguf_path=None)` |
| `RerankerConfig.native()` / `.native_quantized()` | `RerankerConfig.llamacpp()` |

## Rust callers

- **No action for default users.** `Lunaris::open(url)` resolves the
  llama.cpp embedder/reranker automatically when the GGUFs are staged at
  `~/.lunaris/models/granite-embedding-311m-multilingual-r2.Q4_K_M.gguf` and
  `~/.lunaris/models/bge-reranker-v2-m3.Q5_K_M.gguf` (override with
  `LUNARIS_EMBEDDER_GGUF` / `LUNARIS_RERANKER_GGUF`). The MCP server
  stages them lazily on first recall; other deployments download the
  GGUFs out-of-band and verify against the canonical SHA-256s printed by
  `cargo run -p lunaris-bench --bin stage-models -- --help`.
- **Deleted crates**: any direct dependency on `lunaris-embed-native` or
  `lunaris-rerank-native` must move to `lunaris-llamacpp` (feature
  `llamacpp`). The output contracts are unchanged: 768-d L2-normalized
  CLS-pooled embeddings; sigmoid rerank scores ∈ [0, 1].
- **Feature renames**: drop `native`, `embedder-gguf`, `reranker-gguf`,
  `cpu-accelerate`, `cpu-mkl`, `cuda-fa2` from your feature lists. GPU
  offload: build with `--features metal` (or `cuda` / `vulkan`).
- **Build prerequisite**: the `llamacpp` feature (default) compiles
  llama.cpp — you need `cmake` + a C++ toolchain. For a pure-Rust,
  no-inference build (Tier-0 / small devices):
  `default-features = false` → NoopEmbedder/NoopReranker + remote slots.

## Extractor / verifier (graph pipeline)

The in-process candle Gemma-3 backends are gone. To get real extraction:

```bash
export LUNARIS_GRAPH_ENABLED=1               # D-10 gate, still default-off
export LUNARIS_EXTRACT_PROVIDER=minimax      # anthropic|openai|gemini|minimax|openai-compat
export MINIMAX_API_KEY=...
# or any OpenAI-compatible server (Ollama, llama-server, vLLM, LM Studio):
export LUNARIS_EXTRACT_PROVIDER=openai-compat
export LUNARIS_OPENAI_COMPAT_BASE_URL=http://127.0.0.1:11434/v1
export OPENAI_COMPAT_EXTRACT_MODEL=gemma3:4b # keyless allowed for this provider
```

`LUNARIS_VERIFY_PROVIDER` works identically for the verifier. A provider
that is set but fails to construct logs a warning and degrades to Noop —
it never silently falls back to a different backend. Rust callers can
still supply any custom impl via `with_extractor` / `with_verifier`.

## Python / TypeScript SDKs

```python
cfg = EmbedderConfig.llamacpp()                  # staged default GGUF
cfg = EmbedderConfig.llamacpp(gguf_path="/models/granite.gguf")
rr  = RerankerConfig.llamacpp()
```

```ts
const cfg = EmbedderConfig.llamacpp();           // staged default GGUF
const rr  = RerankerConfig.llamacpp({ ggufPath: "/models/bge.gguf" });
```

`native()` / `native_quantized()` (`nativeQuantized()` in TS) still exist
as stubs but **raise immediately** with a migration hint. Wheels/npm
packages built without the `llamacpp` feature (Tier-0) raise a clear
"no-inference build" error from `llamacpp()` — use `noop()` there.

## Operator escape hatch

`lunaris-embed-remote::OllamaEmbedder` (feature `embed-remote`,
`LUNARIS_EMBEDDER_OLLAMA_URL`) survives for air-gapped hosts that cannot
stage GGUFs. It resolves **after** the llama.cpp step, not before.
