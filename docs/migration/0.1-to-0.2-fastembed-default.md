# Lunaris 0.1 → 0.2 Migration — fastembed default

> **Status:** Final — published with v0.2.0 (2026-05-11).
> **Companion to:** `docs/migration/0.1-to-0.2.md` (Scope / RFC 0001). This guide
> covers ONLY the embedder + reranker default-backend flip; everything else in
> the v0.1 → v0.2 upgrade is in the main migration doc.

---

## 1. What changed

Lunaris v0.2 flips the default embedder and reranker backends from
**candle** to **fastembed** (ONNX-runtime, HF Hub auto-download).

| Surface | v0.1 default | v0.2 default | Opt-out env value |
|---------|--------------|--------------|-------------------|
| Embedder | `CandleEmbeddingGemma` (candle 0.10) | `FastembedEmbedder` (fastembed-rs / ORT) | `LUNARIS_EMBEDDER_BACKEND=candle` |
| Reranker | `BgeRerankerV2M3` (candle 0.10) | `FastembedReranker` (fastembed-rs / ORT) | `LUNARIS_RERANKER_BACKEND=candle` |

The flip applies to the `lunaris` umbrella crate's default-feature graph
AND to the standalone `lunaris-embed` / `lunaris-rerank` defaults. Both
the fastembed and candle backends remain compiled into the default `lunaris`
umbrella (`default = ["fastembed", "candle"]`), so operators can swap
between them at runtime via env vars without a rebuild.

**Basis for the flip:** architectural — fastembed runs the full ONNX
EmbeddingGemma 300M forward pass (attention + pooler + `sentence_embedding`
output_key), while Lunaris's candle path is a documented first-layer
shortcut (`embed_tokens.weight × input_ids → mean-pool → L2-normalize`,
no transformer attention). Phase 19's numerical A/B (recall@3, nDCG@10,
p50/p99 latency) remained blocked on operator hardware at v0.2.0 tag-time;
the flip is an **operator-authorised architectural decision** with an
explicit revert commitment if Phase 19 numbers later contradict it. See
`.planning/phases/20-fastembed-adoption/20-02-SCOPE-DECISION.md` for the
full rationale + risk register, and §8 below for the known-issue surface.

## 2. Behaviour change on first `Lunaris::open()` after upgrade

On the first `Lunaris::open(url)` call after upgrading, with env vars
unset, fastembed downloads ONNX model weights from Hugging Face Hub into
the local cache:

- **Embedder:** EmbeddingGemma 300M → `~/.cache/lunaris/models/fastembed/`
  (~600 MB).
- **Reranker:** BGE-Reranker-V2-M3 → same cache root (~600 MB).

Total first-call cost: **~1.2 GB over the network, 30–90 s on average
broadband**. Subsequent calls hit the local cache and are sub-second.

Operators see two log lines at INFO from `lunaris::handle`:

```
INFO lunaris::handle: embedder_backend="fastembed" embedder_backend_resolved
INFO lunaris::handle: reranker_backend="fastembed" reranker_backend_resolved
```

plus the per-backend construction logs from `lunaris-embed` / `lunaris-rerank`
(model name, cache_dir, execution provider). These are emitted **once per
process** — not per `Lunaris::open()` call.

If HF Hub is unreachable AND the cache is cold, construction **fails fast**
with an error from fastembed-rs. Lunaris does **NOT** silently downgrade to
candle on fastembed errors — operators who need air-gapped behaviour must
explicitly opt out (§3).

## 3. Opt-out paths

### 3.1 Runtime env-var opt-out (Rust + HTTP server + SDKs)

Set both env vars before starting the process:

```bash
export LUNARIS_EMBEDDER_BACKEND=candle
export LUNARIS_RERANKER_BACKEND=candle
```

Domain:
- `LUNARIS_EMBEDDER_BACKEND` ∈ `{fastembed, candle, ollama}` (default `fastembed`).
- `LUNARIS_RERANKER_BACKEND` ∈ `{fastembed, candle, noop}` (default `fastembed`).

Parsing: trims whitespace, case-insensitive (`Candle` and `CANDLE` both work).
Empty string is treated as unset → default. **Unknown values fail fast** with
`LunarisError::Storage(Backend("...is not one of [...]..."))` — there is no
silent fallback. This includes typos, so an `LUNARIS_EMBEDDER_BACKEND=cande`
(missing the `l`) will refuse to start rather than silently picking fastembed.

Going candle-only via env vars requires that the **candle model weights
already exist on disk** before first `Lunaris::open()`. Pre-stage them:

```bash
# Embedder
huggingface-cli download google/embeddinggemma-300m \
  --local-dir ~/.cache/lunaris/models/embedding-gemma-300m

# Reranker
huggingface-cli download BAAI/bge-reranker-v2-m3 \
  --local-dir ~/.cache/lunaris/models/bge-reranker-v2-m3
```

(For the reranker, if the cache is missing Lunaris falls back to
`NoopReranker` with a `tracing::warn!` per RETRIEVE-06 — recall still
runs end-to-end, just without the 12 ms cross-encoder pass. Embedder
cache misses surface the actionable `huggingface-cli ...` error and abort
construction.)

### 3.2 Build-time air-gap (zero fastembed/ort/hf-hub in the binary)

For operators on networks where HF Hub is unreachable AND the ORT
prebuilt download is unavailable:

```bash
cargo build -p lunaris --no-default-features --features candle-only
```

This produces a binary with **zero** fastembed, ort, or hf-hub crates in
the transitive `--edges normal` tree. Verified at build time:

```bash
cargo tree -p lunaris --no-default-features --features candle-only \
  --edges normal | grep -cE "fastembed|ort|hf-hub"
# expected: 0
```

This is the load-bearing air-gap escape hatch (Plan 20-03 Task 2, landed
at `b3f4fcc`).

### 3.3 Programmatic override (Rust)

The post-construction swap is unchanged from v0.1 — fastembed default does
not break the API surface:

```rust
use std::sync::Arc;
use lunaris::Lunaris;

let handle = Lunaris::open(url).await?
    .with_embedder(Arc::new(my_custom_embedder))
    .with_reranker(Arc::new(my_custom_reranker));
```

Any `impl Embedder` / `impl Reranker` works. Tests typically pass
`Arc::new(StubEmbedder::new(768))` for determinism.

### 3.4 Programmatic override (Python + TypeScript SDKs)

Phase 21 (shipped at `b4ae9bc` / `c99bd05`) adds `EmbedderConfig` and
`RerankerConfig` factory types in both SDKs:

```python
# Python
from lunaris import Lunaris, EmbedderConfig, RerankerConfig

handle = await Lunaris.open(
    url,
    embedder=EmbedderConfig.fastembed(),   # or .candle() / .ollama() / .from_onnx_path(...)
    reranker=RerankerConfig.fastembed(),   # or .candle() / .noop()
)
```

```typescript
// TypeScript
import { Lunaris, EmbedderConfig, RerankerConfig } from "lunaris";

const handle = await Lunaris.open(url, {
  embedder: EmbedderConfig.fastembed(),
  reranker: RerankerConfig.fastembed(),
});
```

If `embedder` / `reranker` is omitted, the SDK falls back to the same
env-var resolution as the Rust path (fastembed by default).

## 4. Customization API surface

| Layer | Surface | Phase |
|-------|---------|-------|
| Rust embed | `FastembedEmbedder::new(opts)` + `FastembedEmbedder::from_user_defined(bytes, opts)` | 19-01 / 20-01 |
| Rust embed | `Lunaris::with_embedder(Arc<dyn Embedder>)` (post-construction swap) | 02-01 |
| Rust rerank | `FastembedReranker::new(opts)` | 19-04 |
| Rust rerank | `Lunaris::with_reranker(Arc<dyn Reranker>)` | 02-03 |
| Python SDK | `EmbedderConfig.fastembed() \| .candle() \| .ollama() \| .from_onnx_path(path) \| .from_onnx_bytes(bytes)` → `Lunaris.open(url, embedder=...)` | **Phase 21** |
| Python SDK | `RerankerConfig.fastembed() \| .candle() \| .noop()` → `Lunaris.open(url, reranker=...)` | **Phase 21** |
| TypeScript SDK | Same shape, camelCase | **Phase 21** |
| HTTP server | **env vars only** — embedder identity is a deployment concern, not a wire surface (CLAUDE.md HTTP DTO discipline). |
| Build-time | `cargo build --features candle-only` umbrella; per-crate `--features {fastembed, candle, ollama}` for fine-grained control. | 20-03 |

SDK customization mirrors Phase 21 — until Phase 21 ships in your
environment, SDK callers use the env-var path (§3.1).

## 5. Storage-schema constraint (Plan 20-01 dim audit)

**All Lunaris embedders MUST output 768-dimensional vectors.**

Both the candle and fastembed default backends embed EmbeddingGemma 300M
→ 768-d. The Moon FT vector index and the Postgres pgvector column are
both declared as 768-d. The Plan 20-01 Task 4 audit confirmed this is
the operative dim across the storage layer.

Bring-your-own-model via `FastembedEmbedder::from_user_defined(bytes, opts)`
(Rust) or `EmbedderConfig.from_onnx_bytes(...)` / `EmbedderConfig.from_onnx_path(...)`
(Python / TypeScript SDKs) **MUST output 768-d vectors** unless the operator also:

1. Drops + recreates the Moon FT index with the new dimension:
   `FT.DROP INDEX chunks_vec` then `FT.CREATE` with the desired `DIM`.
2. Alters the Postgres pgvector column type:
   `ALTER TABLE chunks ALTER COLUMN embedding TYPE vector(<new_dim>);`
3. Re-ingests all corpora — old 768-d vectors are not re-embeddable in place.

Affected DDL paths:
- Moon: `crates/lunaris-storage-moon/src/init.rs` (`FT.CREATE` calls).
- Postgres: `crates/lunaris-storage-postgres/migrations/*_vector*.sql`
  + `*_scope_partitioning.sql` (the v0.2 base column type).

For the v0.2.0 default flip, **no DDL change is required** — fastembed
emits the same 768-d as candle.

## 6. Verification checklist

After upgrading and starting your process:

- [ ] Logs show `INFO lunaris::handle: embedder_backend="fastembed"` (or
      whichever backend you pinned via env var). One-shot per process.
- [ ] Logs show `INFO ... fastembed embedder constructing` with the cache
      dir from `lunaris-embed::fastembed`. Same for the reranker.
- [ ] On first `Lunaris::open()`, `~/.cache/lunaris/models/fastembed/`
      exists and contains the ONNX model files (look for `model.onnx`
      and `tokenizer.json` per cached model).
- [ ] One sample recall query against a known corpus returns sensible
      results — relevance order roughly matches v0.1 candle baseline
      (the architectural change should *improve* not regress recall;
      monitor closely if you observe the opposite).
- [ ] (Optional) Run a 1-hour mini-soak — point at a representative
      fixture, observe error rate < 0.1% and stable RSS. The full 24 h
      operator-supervised soak is tracked in
      `.planning/phases/20-fastembed-adoption/20-03-TASK-3-DEFERRED.md`.

## 7. Rollback procedure

If the upgrade goes bad — recall regression, latency p99 outside the
25 ms blueprint budget, or HF Hub trust concerns — roll back in one of
three escalating steps:

1. **Env-var revert (no rebuild, no data migration):**
   ```bash
   export LUNARIS_EMBEDDER_BACKEND=candle
   export LUNARIS_RERANKER_BACKEND=candle
   # restart the process
   ```
   Both backends produce 768-d vectors and share the same Moon FT index /
   Postgres pgvector column, so existing data remains queryable. Requires
   candle model weights staged on disk (see §3.1).

2. **Programmatic per-handle revert:**
   ```rust
   let handle = Lunaris::open(url).await?
       .with_embedder(Arc::new(CandleEmbeddingGemma::new(Default::default()).await?))
       .with_reranker(Arc::new(BgeRerankerV2M3::try_new_from_default_cache().await?));
   ```
   Useful for per-deployment partial reverts (e.g., one tenant on candle,
   the rest on fastembed).

3. **Binary version revert:** pin the previous Lunaris version (`0.1.2`)
   in your `Cargo.toml` / `pyproject.toml` / `package.json` and redeploy.
   On-the-wire data remains compatible at the 768-d vector level.

## 8. Known issues

### 8.1 Default flip applied without numerical benchmark

The v0.2.0 default flip was applied under **explicit operator override**
of the Plan 20-02 verdict gate — the Phase 19-03 (embedder A/B) and
Phase 19-04 (reranker A/B) numerical benchmarks both remained
**BLOCKED on operator-supervised hardware** at v0.2.0 tag time. The
decision rests on architectural reasoning (see `20-02-SCOPE-DECISION.md`):
fastembed runs the full ONNX EmbeddingGemma 300M forward pass; the
candle path is a documented first-layer-only shortcut.

**Revert commitment:** if Phase 19 benchmarks subsequently show
fastembed recall@3 regression > 5 % absolute vs candle on a
representative corpus, the operator commits to **revert the default flip
before tagging the next v0.2 patch release**. The single-step env-var
rollback path (§7.1) is the documented mitigation in the interim.

### 8.2 First-call HF Hub fetch can block 30–90 s

Documented in §2. Mitigations:
- Operators on slow networks should run a warm-up `Lunaris::open()` at
  deployment time, not on the request hot path.
- Air-gapped operators use `LUNARIS_*_BACKEND=candle` (§3.1) or the
  `candle-only` build (§3.2).

### 8.3 fastembed cache-miss errors are not silently downgraded

When `LUNARIS_EMBEDDER_BACKEND=fastembed` (the default) is active and
HF Hub is unreachable AND the cache is cold, `Lunaris::open()` returns
an error rather than falling back to candle. This is deliberate — silent
backend swaps would hide a network misconfiguration from operators.
The candle **reranker** branch retains the RETRIEVE-06 "missing weights →
NoopReranker + warn" fallback (recall still runs without the cross-encoder
pass); fastembed errors fail loud.

### 8.4 Phase 19 / Phase 20 soak evidence remains operator-pending

The 24-hour soak (Plan 20-03 Task 3) is BLOCKED on operator hardware.
See `.planning/phases/20-fastembed-adoption/20-03-TASK-3-DEFERRED.md`
for the deferred-task runbook + the operator gate that signs off
v0.2-fastembed-default for production.
