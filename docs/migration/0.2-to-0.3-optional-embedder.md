# 0.2 → 0.3 migration — optional embedder backends

Date: 2026-05-13. Source: Phase 22 (operator-asked).

## TL;DR

`cargo build -p lunaris-memory` no longer pulls fastembed / candle /
ONNX Runtime / hf-hub. The umbrella crate's `default = []` now ships
**zero embedder backends**. `Lunaris::open(url)` still succeeds in this
configuration — the resolver lands on a new `NoopEmbedder` (zero vectors,
configurable dim) with a one-shot `tracing::warn!` so the operator sees
that vector recall is dead until they enable a real backend or pass one
through the new `Lunaris::open_with_embedder` constructor.

## What changed

### `crates/lunaris/Cargo.toml`

```diff
-default = ["fastembed", "candle"]
+default     = []
+recommended = ["fastembed", "candle"]
```

The previous default (`fastembed + candle`) moved to a `recommended`
meta-feature for one-flag opt-in: `cargo build -p lunaris-memory
--features recommended` reproduces the v0.2 build matrix exactly.

### `LUNARIS_EMBEDDER_BACKEND`

New value: `noop`. Domain is now `{fastembed, candle, ollama, noop}`.
Unset / empty selects the first compiled-in backend in the priority
order `fastembed > candle > ollama`, falling through to `noop` if none
is enabled. Explicit `LUNARIS_EMBEDDER_BACKEND=<X>` against a build that
did not compile feature `<X>` still errors fast with the existing
actionable message.

### New env var: `LUNARIS_EMBED_DIM`

Controls the dim of the `noop` embedder when it is the resolved
backend. Positive integer; non-numeric / `0` / unset all fall back to
`lunaris_embed::NOOP_DEFAULT_DIM` (768) with a `tracing::warn!` on the
invalid cases. Ignored for real backends (their dim is fixed by the
model).

### New API: `Lunaris::open_with_embedder(url, embedder)`

Bypasses the env-var resolver and uses the caller-supplied
`Arc<dyn Embedder>` directly. Use when:

- You need to pin a specific vector dim **before** Moon's `FT.CREATE`
  fires on first open (Moon's index dim is sticky once created — see
  the operator footgun in
  `crates/lunaris-storage-moon/src/client.rs::connect_with_dim`).
- The build has no embedder feature compiled in and you want a real
  embedder anyway (BYO).
- You want a `NoopEmbedder` at a specific dim:

  ```rust
  use std::sync::Arc;
  use lunaris::Lunaris;
  use lunaris_embed::NoopEmbedder;

  let handle = Lunaris::open_with_embedder(
      "moon://localhost:6390",
      Arc::new(NoopEmbedder::new(1536)),
  ).await?;
  ```

### Python / TypeScript SDKs

`EmbedderConfig.noop(dim=768)` / `EmbedderConfig.noop(384)` now construct
a zero-vector embedder. Existing `EmbedderConfig.fastembed()` /
`.ollama()` / `.from_onnx_*()` factories are unchanged. The SDK
`Cargo.toml` files still hard-code `lunaris-embed`'s `fastembed` +
`ollama` features for "batteries-included" wheel builds — operators who
want a lean SDK wheel can build with `lunaris-py/lunaris-ts` features
pruned (deferred to a follow-up phase).

## Upgrade matrix

| You were doing                                              | Do this instead                                                                |
| ----------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `cargo build -p lunaris-memory`                             | `cargo build -p lunaris-memory --features recommended` (or pick a real backend explicitly) |
| `cargo build -p lunaris-memory --features fastembed`        | unchanged — explicit feature flags still work                                  |
| `cargo build -p lunaris-memory --no-default-features` to dodge ORT/candle | unchanged — `Lunaris::open()` now succeeds with a `NoopEmbedder` instead of erroring |
| `LUNARIS_EMBEDDER_BACKEND=fastembed` (default reliance)     | unchanged when `--features fastembed` is on; otherwise rebuild or accept the noop fallback |
| `Lunaris::open(...).await?.with_embedder(...)` to swap dim against Moon | switch to `Lunaris::open_with_embedder(url, embedder)` so the dim is pinned before `FT.CREATE` |

## Verifying

```bash
# Lean default build — no ORT, no candle, no hf-hub.
cargo tree -p lunaris-memory --no-default-features --edges normal \
  | grep -cE "fastembed|ort|hf-hub|candle"
# Expected: 0

# Default-features build also opts into zero backends:
cargo tree -p lunaris-memory --edges normal \
  | grep -cE "fastembed|ort|hf-hub|candle"
# Expected: 0

# Recommended bundle reproduces v0.2 behaviour.
cargo tree -p lunaris-memory --features recommended --edges normal \
  | grep -cE "fastembed|ort|hf-hub|candle"
# Expected: > 0
```
