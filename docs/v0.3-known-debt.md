# v0.3 Known Debt

This page tracks debt items intentionally deferred from P0 #1 Wave 2
(Scope::dev() eradication) to v0.3. Each item carries an allow-list
marker (`// scope-dev-allowed: <reason>`) in the source so the
`cargo xtask check-scope` guard can distinguish audited debt from
accidental regressions.

## verify/consolidate supervisor activation (v0.3-blocker)

`crates/lunaris-verify/src/worker.rs` and
`crates/lunaris-consolidate/src/worker.rs` ship deprecated
single-topic wrappers that internally use `Scope::dev()` because their
queue envelopes are scope-less. The canonical replacement is
`VerifySupervisor` / `ConsolidateSupervisor` with per-scope
`register_scope` activation, plumbed through
`VerifyPipelineHandle::enable` / `ConsolidatorPipelineHandle::enable`.

The deprecation is in place (Wave 3F) but the production callers in
`verify_pipeline.rs:163-167` and `consolidator_pipeline.rs:139-143`
use the deprecated path under `#[allow(deprecated)]` with explicit
"Migration to supervisor is a v0.3 task" comments.

The same class covers
`crates/lunaris/src/primitives/working_memory.rs:187`
(`drain_consolidate_events` subscribe — global CONSOLIDATE_TOPIC),
which also waits for Wave 3F per-scope queue routing.

Out of scope for P0 #1 Wave 2 (Scope::dev eradication). Tracked as a
separate phase; the allow-list markers in `worker.rs` files keep this
debt visible to the CI grep guard.

## `Lunaris::forget` — `ScopedLunaris::forget` superseder

`Lunaris::forget` is `#[deprecated]` as of P0 #1 Wave 2. Internally it
still routes its `atomic_write` / `read_as_of` / `scan_range` calls
through `Scope::dev()` because the queue envelope and ForgetRequest
payload do not carry the scope. Removing the deprecated method (and
its `Scope::dev()` allow-list markers) is a v0.4 task per
`scope-dev-allowed: deprecated-Lunaris::forget-routes-here-until-v0.4`.

The canonical entry point is `engine.scoped(scope).forget(request)`,
which threads the bound scope through every storage call.

## `Lunaris::recall` queue-depth health check

`crates/lunaris/src/recall.rs:126` calls
`storage.queue_depth(&Scope::dev(), VERIFY_TOPIC, 0)`. The verify
topic is a global broadcast across scopes; per-scope queue-depth
introspection would require backend-side topic partitioning that's a
separate RFC. Tracked as Wave 1E (introduce
`ScopedLunaris::recall_with_degraded_check` once the routing exists).

## `RetrievalBuilder` bare-recall default scope

`crates/lunaris-retrieve/src/builder.rs` seeds `Scope::dev()` as the
default so `Lunaris::recall().execute(...)` (the unscoped legacy path)
keeps working. The builder now warns at `execute()` time when the
scope is still the default. `ScopedLunaris::recall` /
`ScopedLunaris::dsl()` both call `with_scope(self.scope)` so adopters
who migrate to the scoped API never hit the warn or the default.

Removing the bare path entirely is a v0.4 task — tracked alongside the
`Lunaris::forget` removal.

## Graph scoring — optional column emission (P0 #4 Wave 3)

`Graph::anchored`'s `retrieve()` scores hits via

    score = (edge_weight_product / (1.0 + path_length)) * anchor_confidence

reading `path_length`, `edge_weight_product`, and `anchor_confidence` by
header name from `GraphResult` (documented on `lunaris_core::storage::types::GraphResult`).
The operator is wire-additive: when these headers are absent, the formula
substitutes documented defaults (`i`, `1.0`, `1.0`) so the score reduces to
the pre-Wave-3 `1.0 / (1.0 + i)` — the regression pinned by
`graph_score_back_compat_when_no_new_headers`.

One follow-up task remains after Wave 4 (2026-05-13):

1. **Moon GRAPH.QUERY — emit `path_length` + `edge_weight_product`** —
   **BLOCKED at the Cypher dialect** (Wave 4 Piece C verification,
   2026-05-13). Live `redis-cli` probes against
   `vendor/moon@b24b4d07` (raw output captured in
   `tmp/wave4c-dialect-verification.md` and the PR #4 body) prove the
   following gaps are **parser-level rejections**, not silent-null
   fallbacks:
   - `MATCH p = (n)-[*1..N]-(m)` is reserved for `shortestPath(...)`
     per `vendor/moon/src/graph/cypher/parser/pattern.rs:172-216` —
     bare path-variable binding fails with
     `ERR Cypher parse error: expected shortestPath, found LParen`.
   - `length()` / `reduce()` / `relationships()` / `nodes()` are
     absent from the function table at
     `vendor/moon/src/graph/cypher/executor/eval.rs:116-227` (only
     `id`, `labels`, `type`, `size`, `tointeger`/`toint`, `tofloat`,
     `tostring`, `count`, `collect`, `coalesce` are recognised).
     `length(list)` parses but evaluates to `Null`.
   - List comprehension `[x in xs | f(x)]` has no grammar production
     in `vendor/moon/src/graph/cypher/parser/expr.rs` — the `|` token
     is rejected before the executor sees it.
   - The variable-length BFS executor at
     `vendor/moon/src/graph/cypher/executor/read.rs:132-174` **never
     binds the edge variable** for `max_hops > 1` (only single-hop,
     read.rs:127-129) and never records per-row hop count, so even a
     client-side weight-list fold workaround is impossible — Moon
     simply does not carry per-edge state out of the traversal.

   Because the failure mode is a parser-reject (hard
   `StorageError::Backend`), the operator's wire-additive missing-header
   fallback — pinned by `graph_score_back_compat_when_no_new_headers` —
   does **not** activate. Sending Piece A's `length(p)` /
   `reduce(...)` template unconditionally would zero-out Moon-backed
   graph traversal in `Graph::anchored`, not gracefully degrade.

   **Owner action (v0.4 follow-up, blocks Piece A on Moon):**
   - Make the operator backend-aware so Moon keeps the legacy
     `MATCH (n)-[*1..N]-(m) RETURN DISTINCT m.id_hex AS id, …`
     template (the v0.3 status quo), and only Postgres/AGE receives
     the new path-metrics columns. The Wave 4 Piece C Moon-SDK parser
     (`crates/lunaris-storage-moon/src/graph.rs::parse_graph_reply`)
     is **already** N-column-ready — pinned by
     `parse_six_column_reply_with_path_metrics` — so the SDK side will
     not require a change when the operator switches templates.
   - OR upstream a Moon Cypher patch that adds `length()` /
     `relationships()` to `eval.rs`, plumbs edge-variable binding
     through the variable-length BFS branch in `read.rs`, and accepts
     bare `p = ...` path-variable bindings in `pattern.rs`. Multi-week
     Moon-team effort; tracked outside the Lunaris repo.

Closed in v0.4 (Wave 4 piece A): **EntityId confidence plumbing.**
`Graph::anchored(Vec<(EntityId, f32)>, hops)` now takes per-seed
confidence; when the dialect tier is PathMetrics or Full the operator
joins the `source_entity_id` Cypher column against the seed map to
synthesize `anchor_confidence`. The 1.0 default still fires when the
column is absent (Legacy tier, OR a backend that hasn't been upgraded
to the multi-column return type).

Closed in v0.4 (Wave 4 piece B): **Postgres AGE multi-column return type.**
`crates/lunaris-storage-postgres/src/graph.rs` now decomposes the AGE
result into `id` / `name` / `type` / `path_length` /
`edge_weight_product` / `source_entity_id` columns with per-column
agtype decoding. The adapter advertises `CypherDialect::PathMetrics`.

Closed in v0.4 (Wave 4 amendment, 2026-05-13):
**Capability-driven Cypher dialect dispatch.** `StorageCapabilities`
now carries a `CypherDialect::{Legacy, PathMetrics, Full}` enum.
`crates/lunaris-retrieve/src/operators/graph.rs` reads
`ctx.storage.capabilities().cypher_dialect` at retrieve-time and
picks one of three Cypher templates. Defaults are:

| Backend          | Tier        | Reason |
|------------------|-------------|--------|
| Moon             | Legacy      | Parser + function-table restrictions (primary-source pinned in commit body of the Wave-4 amendment) |
| Postgres (AGE 1.5) | PathMetrics | Supports `MATCH p = ...` + `length(p)` + `source_entity_id`; rejects `reduce()` at `\|` token |
| Embedded         | Legacy      | No graph support; `graph_traverse` returns `NotSupported` |

Promotion to a higher tier requires a primary-source dialect probe
against the live backend. Test fixtures default to `Legacy` via
`CypherDialect::default()` so a new backend NEVER silently promotes.

The wire contract (the optional headers + their defaults) is pinned
on `GraphResult`'s docstring so backends can opt in independently
without operator-side churn.

## How the CI guard works

`cargo xtask check-scope` (or `make check-scope-leaks`) walks every
`.rs` file under `crates/` and flags any `Scope::dev()` call site
without a `// scope-dev-allowed: <reason>` marker on the same line or
the leading comment line. Inline `#[cfg(test)] mod ... { ... }`
blocks, doc comments, and the file-path allow-list
(test/bench crates, the `Scope` impl, SDK conformance shims) are
skipped wholesale. See `xtask/src/check_scope.rs` for the full
spec — and its unit tests under `xtask/src/check_scope.rs#tests`.
