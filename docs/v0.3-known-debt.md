# v0.3 Known Debt

This page tracks debt items intentionally deferred from P0 #1 Wave 2
(Scope::dev() eradication) to v0.3. Each item carries an allow-list
marker (`// scope-dev-allowed: <reason>`) in the source so the
`cargo xtask check-scope` guard can distinguish audited debt from
accidental regressions.

## verify/consolidate supervisor activation (v0.3-blocker)

`crates/lunaris-verify/src/worker.rs` and
`crates/lunaris-consolidate/src/worker.rs` ship deprecated
single-topic wrappers that internally use `Scope::dev()` because their
queue envelopes are scope-less. The canonical replacement is
`VerifySupervisor` / `ConsolidateSupervisor` with per-scope
`register_scope` activation, plumbed through
`VerifyPipelineHandle::enable` / `ConsolidatorPipelineHandle::enable`.

The deprecation is in place (Wave 3F) but the production callers in
`verify_pipeline.rs:163-167` and `consolidator_pipeline.rs:139-143`
use the deprecated path under `#[allow(deprecated)]` with explicit
"Migration to supervisor is a v0.3 task" comments.

The same class covers
`crates/lunaris/src/primitives/working_memory.rs:187`
(`drain_consolidate_events` subscribe — global CONSOLIDATE_TOPIC),
which also waits for Wave 3F per-scope queue routing.

Out of scope for P0 #1 Wave 2 (Scope::dev eradication). Tracked as a
separate phase; the allow-list markers in `worker.rs` files keep this
debt visible to the CI grep guard.

## `Lunaris::forget` — `ScopedLunaris::forget` superseder

`Lunaris::forget` is `#[deprecated]` as of P0 #1 Wave 2. Internally it
still routes its `atomic_write` / `read_as_of` / `scan_range` calls
through `Scope::dev()` because the queue envelope and ForgetRequest
payload do not carry the scope. Removing the deprecated method (and
its `Scope::dev()` allow-list markers) is a v0.4 task per
`scope-dev-allowed: deprecated-Lunaris::forget-routes-here-until-v0.4`.

The canonical entry point is `engine.scoped(scope).forget(request)`,
which threads the bound scope through every storage call.

## `Lunaris::recall` queue-depth health check

`crates/lunaris/src/recall.rs:126` calls
`storage.queue_depth(&Scope::dev(), VERIFY_TOPIC, 0)`. The verify
topic is a global broadcast across scopes; per-scope queue-depth
introspection would require backend-side topic partitioning that's a
separate RFC. Tracked as Wave 1E (introduce
`ScopedLunaris::recall_with_degraded_check` once the routing exists).

## `RetrievalBuilder` bare-recall default scope

`crates/lunaris-retrieve/src/builder.rs` seeds `Scope::dev()` as the
default so `Lunaris::recall().execute(...)` (the unscoped legacy path)
keeps working. The builder now warns at `execute()` time when the
scope is still the default. `ScopedLunaris::recall` /
`ScopedLunaris::dsl()` both call `with_scope(self.scope)` so adopters
who migrate to the scoped API never hit the warn or the default.

Removing the bare path entirely is a v0.4 task — tracked alongside the
`Lunaris::forget` removal.

## How the CI guard works

`cargo xtask check-scope` (or `make check-scope-leaks`) walks every
`.rs` file under `crates/` and flags any `Scope::dev()` call site
without a `// scope-dev-allowed: <reason>` marker on the same line or
the leading comment line. Inline `#[cfg(test)] mod ... { ... }`
blocks, doc comments, and the file-path allow-list
(test/bench crates, the `Scope` impl, SDK conformance shims) are
skipped wholesale. See `xtask/src/check_scope.rs` for the full
spec — and its unit tests under `xtask/src/check_scope.rs#tests`.
