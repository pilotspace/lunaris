# v0.4 — Rerank Reference-Fixture Population

N-04 Deliverable 7. Documents the runbook for populating the
"reference rerank scores" fixture that the live FP32-vs-HF reranker
drift gate compares against. The drift gate itself is operator-only
(N-03 contract: the engineer who built the candle path cannot validate
it against ground truth from inside the same harness).

**Owner:** Lunaris on-call operator.

## When to re-run

* Before promoting a new reranker checkpoint (HF revision bump).
* After any change to the candle inference path in
  `crates/lunaris-rerank/src/bge.rs`.
* On a quarterly cadence as a smoke check.

## Inputs

| Artifact                          | Source                                        |
|-----------------------------------|-----------------------------------------------|
| Query corpus                      | `crates/lunaris-conformance/fixtures/rerank-corpus.jsonl` (50 query × 10 candidate rows) |
| HF reference model                | `BAAI/bge-reranker-v2-m3` (FP32 safetensors)  |
| Tokenizer                         | Same repo, `tokenizer.json` + `tokenizer_config.json` |
| Cache layout                      | `<cache>/lunaris/models/bge-reranker-v2-m3/`  |

If the corpus fixture does not yet exist (status as of N-04: it does
not), the operator's first task is to materialise it from the LoCoMo
eval seed — see §"Bootstrap the corpus" below.

## Procedure

1. **Stage the HF weights** (idempotent):

   ```sh
   cargo run --release -p lunaris-bench --bin stage-models -- \
       --cache-dir ~/.cache/lunaris/models
   ```

   Verify the SHA-256 of `model.safetensors` matches the value in the
   HF model card. (N-04 reserves `ModelEntry::sha256` for explicit pins
   on GGUF bundles; safetensors today rely on HF Hub's own checksum
   layer, but the operator MUST eyeball the size on disk against the HF
   card to catch a half-downloaded file.)

2. **Run the reference scorer** (Python, against the HF transformers
   reference impl — distinct codepath from candle, which is exactly
   what makes the drift gate meaningful):

   ```sh
   python3 scripts/spike-generate-reference-rerank-scores.py \
       --corpus crates/lunaris-conformance/fixtures/rerank-corpus.jsonl \
       --model-dir ~/.cache/lunaris/models/bge-reranker-v2-m3 \
       --out crates/lunaris-conformance/fixtures/rerank-reference-scores.jsonl
   ```

   STATUS (N-04): the script does NOT yet exist in `scripts/`. The
   shape of the deliverable when the operator authors it:

   ```python
   # scripts/spike-generate-reference-rerank-scores.py
   #
   # Read JSONL rows of {query, candidates: [text, ...]}; score each
   # (query, candidate) pair with the HF transformers reference impl
   # (CrossEncoder("BAAI/bge-reranker-v2-m3")); emit JSONL rows of
   # {query, candidate_idx, score} in the same row order. NO shuffling,
   # NO threshold filtering — raw float32 scores.
   ```

   The runtime drift gate in `crates/lunaris-rerank/tests/` then
   replays the same corpus through the candle path and asserts
   `|hf_score - candle_score| ≤ 1e-3` per row.

3. **Commit the regenerated fixture** as a single atomic commit:

   ```sh
   git add crates/lunaris-conformance/fixtures/rerank-reference-scores.jsonl
   git commit -m "fixtures(rerank): refresh reference scores against BAAI/bge-reranker-v2-m3 @<hf-sha>" \
                 -m "Replays $(wc -l < crates/lunaris-conformance/fixtures/rerank-corpus.jsonl) query×candidate rows through the HF reference impl." \
                 -m "Drift gate epsilon: 1e-3 per row." \
                 -m "Run by: $(whoami) on $(date -u +%FT%TZ)"
   ```

## Bootstrap the corpus (first time only)

Skip if `crates/lunaris-conformance/fixtures/rerank-corpus.jsonl`
already exists.

```sh
# Sample 50 queries from LoCoMo dev; for each query pull 10
# candidates from the same LoCoMo corpus using the v0.3 lunaris recall
# operator at top-k=10 (NO rerank — we want pre-rerank candidates).
cargo run --release -p lunaris-bench --bin lunaris-evals -- \
    sample-rerank-corpus \
    --eval locomo \
    --n-queries 50 \
    --candidates-per-query 10 \
    --out crates/lunaris-conformance/fixtures/rerank-corpus.jsonl
```

Same caveat as the v0.4-soak runbook: the `sample-rerank-corpus`
subcommand is not yet wired in N-04. Operator stub:

```jsonl
{"query": "...", "candidates": ["...", "...", ...]}
```

50 rows, deterministic seed `0xL1NAR15`.

## Exit criteria

The fixture refresh PASSES iff:

* Every row in `rerank-reference-scores.jsonl` has a finite float
  score (no NaN / inf).
* Row count equals the corpus row count × 10 (one score per
  (query, candidate) pair).
* The follow-up drift gate (`cargo test -p lunaris-rerank
  --test drift_gate --features drift-gate-it`) is green.

ANY failure → roll back the fixture commit, file a regression issue
against the candle inference path, and DO NOT promote the candle
backend further along the rollout.
