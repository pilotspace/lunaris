# v0.4 — 24h Soak Procedure (Operator Runbook)

N-04 Deliverable 6. The release-blocker that the engineer who built
N-01..N-04 cannot run themselves: a 24-hour soak against a Helios
snapshot, sampling RSS / latency / drift on a steady query mix.

**Owner:** Lunaris on-call operator. Run on a dev-box-sized VM, not on
shared infra.

**Pre-flight:** N-04 must be merged. `cargo test --workspace` green on
the soak branch.

## 0. Bench setup

```sh
# Workspace
git fetch origin
git checkout main
cargo build --release -p lunaris-server -p lunaris-bench

# Helios snapshot — copy the latest dev snapshot into the bench tree.
# (Replace the source path with the operator's actual snapshot mount.)
mkdir -p /var/lib/lunaris/soak
rsync -a /mnt/helios-snapshots/latest/ /var/lib/lunaris/soak/data/

# Models — fetch the candle weights this build resolves at runtime.
cargo run --release -p lunaris-bench --bin stage-models -- \
    --cache-dir /var/lib/lunaris/soak/models
```

## 1. Launch lunaris-server against the snapshot

```sh
RUST_LOG=info,lunaris=debug \
LUNARIS_EMBEDDER_DIR=/var/lib/lunaris/soak/models/granite-r2 \
LUNARIS_RERANKER_DIR=/var/lib/lunaris/soak/models/bge-reranker-v2-m3 \
nohup ./target/release/lunaris-server \
    --bind 127.0.0.1:8088 \
    --storage moon://127.0.0.1:6380 \
    > /var/log/lunaris-soak.log 2>&1 &
echo $! > /var/run/lunaris-soak.pid
```

Confirm it's serving:

```sh
curl -s http://127.0.0.1:8088/health | jq .
```

## 2. RSS sampling cadence

Sample every 60 seconds for the full 24h window. macOS:

```sh
PID=$(cat /var/run/lunaris-soak.pid)
while kill -0 "$PID" 2>/dev/null; do
    ps -o rss= -p "$PID" \
      | awk -v ts="$(date -u +%FT%TZ)" '{printf "%s %d\n", ts, $1}' \
      >> /var/log/lunaris-soak-rss.tsv
    sleep 60
done
```

Linux equivalent (procfs):

```sh
PID=$(cat /var/run/lunaris-soak.pid)
while kill -0 "$PID" 2>/dev/null; do
    awk '/VmRSS:/ {printf "%s %d\n", strftime("%FT%TZ", systime(), 1), $2}' \
        /proc/$PID/status >> /var/log/lunaris-soak-rss.tsv
    sleep 60
done
```

Goal: 1440 samples (24 h × 60 / hr). Drift past `baseline + 250 MiB`
inside the first 4 hours = abort + file a regression issue against
N-04. Sustained creep past `baseline + 500 MiB` over 24h = same.

## 3. Query mix

Drive the live binary with the same workload `recall_hot_path` runs in
Criterion. The bench harness ships a replay binary:

```sh
cargo run --release -p lunaris-bench --bin lunaris-evals -- \
    soak \
    --target http://127.0.0.1:8088 \
    --duration 24h \
    --qps 5 \
    --mix "recall:0.7,ingest:0.2,forget:0.1" \
    --queries-from /var/lib/lunaris/soak/data/queries.jsonl \
    --evidence-out /var/log/lunaris-soak-evidence.jsonl
```

If `lunaris-evals soak` is not wired yet (status as of N-04: D-22
budget gauntlet only), fall back to:

```sh
# Adapted recall_hot_path replay; 5 qps × 86400 s = ~430k queries
cargo bench --bench recall_hot_path -p lunaris-bench -- \
    --noplot --measurement-time 86400 \
    --output-format bencher \
    > /var/log/lunaris-soak-recall.txt
```

## 4. Latency sampling

Concurrent with the query mix, sample p50 / p99 every 5 min. The
recall_hot_path bench emits Criterion bencher format which already
includes p50; for live p99 from the server itself, scrape its Prometheus
endpoint:

```sh
while kill -0 "$(cat /var/run/lunaris-soak.pid)" 2>/dev/null; do
    curl -s http://127.0.0.1:8088/metrics \
      | grep -E '^lunaris_recall_latency_(p50|p99)_ms ' \
      | awk -v ts="$(date -u +%FT%TZ)" '{printf "%s %s %s\n", ts, $1, $2}' \
      >> /var/log/lunaris-soak-latency.tsv
    sleep 300
done
```

## 5. Exit criteria

The soak PASSES iff ALL of the following hold over the 24h window:

| Gate          | Threshold                                       | Source                                  |
|---------------|-------------------------------------------------|-----------------------------------------|
| Recall p50    | ≤ 25 ms (sub-25ms blueprint contract)           | CLAUDE.md "Core Value"                  |
| Recall p99    | ≤ 100 ms (4× p50 budget)                        | RETRIEVE-06                             |
| RSS drift     | ≤ baseline + 500 MiB over 24h                   | This runbook §2                         |
| Restart count | 0                                               | `journalctl -u lunaris-soak` (or PID watch) |
| Drift gate    | live FP32 vs HF reranker scores within ε = 1e-3 | N-03 drift contract                     |

ANY failure → abort and file a v0.4-blocking regression issue with:

  * `/var/log/lunaris-soak.log`
  * `/var/log/lunaris-soak-rss.tsv`
  * `/var/log/lunaris-soak-latency.tsv`
  * `/var/log/lunaris-soak-evidence.jsonl`
  * Output of `cargo run --release -p lunaris-bench --bin stage-models -- --dry-run`
    so we can prove which model SHAs the soak ran against.

## 6. Teardown

```sh
kill "$(cat /var/run/lunaris-soak.pid)"
rm -f /var/run/lunaris-soak.pid
# Archive logs to release evidence S3 bucket; see release-preflight.sh.

```
