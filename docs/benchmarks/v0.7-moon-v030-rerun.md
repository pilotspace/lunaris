# v0.7 benchmark rerun — Moon v0.3.0, native Q4 GGUF embedder

ADD task `bench-rerun-v030` (milestone `moon-v030-exploit`, contract FROZEN
@ v1, 2026-06-11 — refined at freeze to use the 4-bit granite-311m embedder).
Re-validates the sub-25 ms recall contract on Moon **v0.3.0** (after the
typed-MQ / decay / Navigate / quantization / HOTKEYS integration work) and
sizes the Navigate operator's recall edge for the first time.

## Headline — the 25 ms contract holds with a wide margin

| Pass | p50 | p95 | p99 | What it measures |
|---|---|---|---|---|
| **Retrieval-only** (noop query embed) | **3.1 ms** | 3.4 ms | **3.6 ms** | The engine: Moon FT.SEARCH + RRF fuse + hydrate — the path the p50 < 25 ms contract is written against |
| End-to-end (live Q4 GGUF query embed) | 61.5 ms | 101.3 ms | 114.1 ms | Above + in-process 4-bit granite-311m embedding of each query on CPU |

The contract is judged on retrieval-only — that is the decomposition the
v0.2.x strict-replay methodology established (embed out of the loop,
apples-to-apples). **PASS: p99 3.6 ms vs the 25 ms p50 contract.** The
~58 ms gap to end-to-end is the Q4 query-embedding compute itself, not the
engine; it is the same lesson as the original "86 ms lesson", now with the
hop being in-process CPU inference instead of an HTTP server.

### Comparison against the 2026-04-23 baseline — with the corpus-size caveat

| Run | Corpus | Retrieval-path p50 / p99 |
|---|---|---|
| 2026-04-23 strict replay (Moon v0.2.x era) — **retracted, kept for history** ‡ | 10,000 docs × 1,000 queries, k=3 | 10.3 ms / 20.8 ms |
| 2026-06-11 retrieval-only (Moon v0.3.0) | 3,000 docs × 300 queries | 3.1 ms / 3.6 ms |

‡ **The 2026-04-23 row is a historical record, not a live claim.** It was
measured on Ollama + EmbeddingGemma 300M — removed in v0.4, and the whole
candle stack removed again in v0.6 — at k=3, and its cited methodology page
(`docs/benchmarks/v0.2.x/README.md`) was never populated with captured
numbers. It was retracted repo-wide on 2026-08-21. The current latency
anchor is the GA-2b envelope in
[`capacity.md`](../operations/capacity.md): p50 19.2–22.4 ms /
p99 23.4–24.4 ms at 100k documents per scope.

**Do not read this as a 3× speedup.** The corpora differ 3.3× in size, and the
strict-replay path still paid a localhost HTTP hop to the replay server while
the retrieval-only pass embeds via an in-process noop. The honest claims are:
(1) the contract holds on v0.3.0, (2) the tail is flat (p99 ≈ p50, consistent
with the v0.6 hydration-fanout A/B), and (3) nothing in the v0.3.0 integration
work (typed MQ, decay, Navigate wiring, quantization plumb-through, HOTKEYS
polling) regressed the hot path. A like-for-like 10k×1k rerun stays on the
books as follow-up before quoting cross-version deltas.

| MRR | 0.749 | 0.773 |

In the same band as the 2026-04-23 direct run (recall@3 86% on 10k docs with
FP16-class embeddings): the **4-bit quantized embedder is not visibly costing
recall** at this scale — the spread between splits (±2 pts) is as large as any
quantization effect.

## Navigate A/B — first sized recall edge (Moon v0.3.0 `FT.NAVIGATE`)

`cargo test -p lunaris-storage-moon --features moon-it --test navigate_ab_bench`
(live Moon @ 6390): 500 background distractors + 25 clusters, each with a
vector-near anchor graph-chained (2 hops) to a vector-far target; k=5, 768-d.

```
NAV A/B VERDICT: plain=0.00 nav=1.00 plain_p50=0.37ms nav_p50=0.42ms
                 (graph-linked targets, n=500+25x3, k=5, hops=2, 768-d)
```

On graph-linked corpora the Navigate operator recovers targets plain vector
search **cannot reach at any k near 5** (0/25 vs 25/25), for ~0.05 ms of added
p50. The qualifier matters: the edge exists **only** where graph links carry
the signal — on link-free corpora Navigate degrades to plain search plus a
no-op hop.

## Reproduction checklist

1. Build the GGUF wheel: `maturin develop --uv --release --features embedder-gguf -m crates/lunaris-py/Cargo.toml` (venv with `datasets python-ulid redis psutil`).
2. GGUF at `~/.cache/lunaris/spike/granite-r2/gguf/granite-r2-311m-Q4_K_M.gguf` (or `LUNARIS_BENCH_GGUF`).
3. Fresh Moon v0.3.0 on 6390 (`vendor/moon/target/release/moon --port 6390 --dir <fresh>`); stale pre-v0.3.0 servers on default ports cause FT._LIST failures.
4. Run the command above; the Navigate A/B via the cargo test in `crates/lunaris-storage-moon/tests/navigate_ab_bench.rs`.
