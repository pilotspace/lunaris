# v0.4 O-01 — per-device perf baselines

**Status:** O-01 landing (worktree branch `o01-backend-tuning`). The
backend tuning code is in place; numbers in this table are produced by
running `cargo bench -p lunaris-bench --features <backend> --bench
per_device` against real weights on the matching hardware. The O-01
author's host is macOS / Apple Silicon arm64, so only the CPU + Metal
rows can be measured locally; CUDA + aarch64 rows are TBD on O-03's
self-hosted runners.

## Gate table (HARDWARE-OPTIMIZATION-ROADMAP §26-37)

| Host                          | Embed p50 | Embed p99 | Rerank p50 (K=10) |
|-------------------------------|-----------|-----------|--------------------|
| Apple Silicon (Metal)         | ≤ 5 ms    | ≤ 15 ms   | ≤ 40 ms            |
| NVIDIA sm_80+ (CUDA)          | ≤ 3 ms    | ≤ 10 ms   | ≤ 25 ms            |
| x86_64 CPU + Accelerate/MKL   | ≤ 40 ms   | ≤ 90 ms   | ≤ 300 ms           |
| aarch64 CPU + NEON            | ≤ 80 ms   | ≤ 200 ms  | ≤ 600 ms           |

All gates: batch=8 (embed) / K=10 (rerank), FP16 weights (Q4 path covered
separately by `embedder-gguf` / `reranker-gguf` features).

## How to measure

```bash
# Provide weights via env vars (paths to the granite-r2 + bge-reranker
# safetensors / tokenizer / config triples).
export GRANITE_R2_WEIGHTS_PATH=...
export GRANITE_R2_TOKENIZER_PATH=...
export GRANITE_R2_CONFIG_PATH=...
export BGE_RERANKER_WEIGHTS_PATH=...
export BGE_RERANKER_TOKENIZER_PATH=...
export BGE_RERANKER_CONFIG_PATH=...

# Apple Silicon Metal
cargo bench -p lunaris-bench --features metal --bench per_device

# macOS CPU + Accelerate
cargo bench -p lunaris-bench --features cpu-accelerate --bench per_device

# Linux CPU + MKL
cargo bench -p lunaris-bench --features cpu-mkl --bench per_device

# Linux CUDA
cargo bench -p lunaris-bench --features cuda --bench per_device

# Linux CUDA + FlashAttention 2 (risk: alternating-attention compose)
cargo bench -p lunaris-bench --features cuda-fa2 --bench per_device
```

Criterion outputs land at
`target/criterion/embed/<backend>/batch_8/` and
`target/criterion/rerank/<backend>/k10/`.

`p50` reads from Criterion's `estimates.json` → `median.point_estimate`
(value is in nanoseconds; divide by 1e6 for ms).
`p99` reads from the raw `sample.json` and is computed as the 99th
percentile of the per-iteration timing list.

## O-03 baseline lock

O-03 will adopt the `v0.4-O01` `--save-baseline` tag against this bench so
PRs can `--baseline v0.4-O01` and fail on >5% regression. The numbers in
this file become the regression-gate floor at that point.

## O-01 author's local notes (host: macOS / Apple Silicon arm64)

- Granite-r2 + bge-reranker-v2-m3 safetensors are NOT cached locally as of
  the O-01-F landing commit. The bench harness is verified to compile
  under `--features metal`, `--features cpu-accelerate`, and the default
  feature set; running it without weights produces a clean `skip:
  granite-r2 weights env vars unset` notice (see `per_device.rs`
  `weights_triple()`).
- CUDA build on this host fails at the cudarc build script (no `nvcc` on
  macOS), as expected and documented in `cuda_notes.rs`.
- aarch64 path is code-only — no Linux ARM hardware on this host.

The first real measurements land when O-03 stands up the self-hosted
runners or when a follow-up commit stages the weights via
`scripts/stage-models.sh` (HF-Hub stager from N-04 D5) and runs the bench
on this same host. Both paths are out-of-scope for O-01.
