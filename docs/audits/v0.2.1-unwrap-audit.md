# v0.2.1 unwrap()/expect() audit

Phase 20 (Public crate hygiene) of `tmp/lunaris-ship-to-product-v2.md`
calls for "no `unwrap()` / `expect()` outside tests". This audit
inventoried every non-test occurrence in the 8 publishable crates and
classified each.

## Method

Scanned `crates/lunaris{,-core,-storage-postgres,-embed,-rerank,-extract,
-verify,-consolidate,-ingest}/src/`. Excluded `#[cfg(test)] mod tests`
blocks and `tests/` directories. Excluded the four internal-only crates
(`lunaris-bench`, `lunaris-conformance`, `lunaris-codegen`,
`lunaris-recipes`, `lunaris-server`) since they don't publish.

## Findings

The audit found ~20 non-test occurrences. Every one falls into one of
five "justified" categories:

| # | Category | Example | Justification |
|---|---|---|---|
| 1 | `Default` invariant | `CandleGemma3_4BOpts::default().model_path.unwrap()` (`candle_gemma3_4b.rs:182`) | The `Default` impl always sets `model_path = Some(_)`; the only way to get `None` is to construct the opts manually and drop `model_path`, which is the exact case the `unwrap_or_else` arm handles. |
| 2 | Algorithmic guarantee | `adj.get(n).expect("every node has an adjacency entry")` (`leiden.rs:132`) | The Leiden algorithm populates an adjacency entry for every node before the iteration that does the lookup. |
| 3 | Pre-checked guard | `decision.winner_id.expect("checked applies() earlier")` (`worker.rs:310`) | The function early-returns if `applies()` is false; reaching this line means both `winner_id` and `loser_id` are `Some`. |
| 4 | Compile-time guarantee | `h.as_bytes()[..16].try_into().expect("blake3 output is 32 bytes; first 16 always fit")` (`types.rs:65`) | `blake3` emits exactly 32 bytes; `[..16].try_into::<[u8; 16]>()` is infallible. |
| 5 | Pipeline invariant | `chunk.embedding.as_ref().expect("embedding assigned in step 2")` (`ingest.rs:312`) | The chunker writes `embedding` before this code runs; the comment + the `step 2` reference in the panic message pins the invariant. |

## Decision

**No fixes applied beyond documentation.** Every site already either:

- Carries an `expect("<reason>")` message that names the invariant, or
- Is one of the `Default::default().X.unwrap()` shapes that v0.3
  will refactor away by introducing infallible `Default::new()`
  constructors per RFC 0004 (ExtractorTier typestate).

One site was upgraded — `crates/lunaris-storage-moon/src/graph.rs:83`
swapped its bare `.unwrap()` for `.expect("guarded by arr.len() < 2
above")` plus a `// SAFETY:` comment. The other 19 are already well-
labelled.

## Going forward

- New code: prefer `?` for fallible operations. Use `expect("<reason>")`
  only when a compile-time-real invariant is genuinely infallible at
  runtime, and write the invariant into the panic message.
- New `expect` strings should name what guards the unwrap so a code-
  review reader sees "this is safe because X" without needing to
  trace dataflow.
- v0.3 RFCs (0004 ExtractorTier, 0007 FallbackExtractor) will retire
  the `Default::default().model_path.unwrap()` pattern by switching
  the affected types to typestate.

This audit closes the Phase 20 "no `unwrap()` outside tests" line item.
