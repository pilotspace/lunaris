sort-en-1
In Python, you can sort a list in place using `list.sort()` or get a new sorted copy with `sorted(list)`. Both accept a `key=` callable for custom orderings and a `reverse=True` flag for descending order. The underlying algorithm is Timsort, a hybrid stable sort that runs in O(n log n) worst case.
sort-en-2
Quicksort is a divide-and-conquer comparison sort that picks a pivot and partitions the array into elements less than and greater than the pivot. Average time complexity is O(n log n) but worst case is O(n^2) when the pivot is always the smallest or largest element.
sort-en-3
Merge sort is a stable, divide-and-conquer sort with guaranteed O(n log n) time complexity. It recursively splits the input into halves, sorts each half, then merges the two sorted halves into one. It requires O(n) auxiliary space, unlike quicksort.
sort-en-4
To sort a list of dictionaries in Python by a specific key, pass a lambda to the `key` argument: `sorted(items, key=lambda x: x['age'])`. The same pattern works with `list.sort()`. For multiple keys, return a tuple from the lambda.
sort-en-5
Heap sort uses a binary heap data structure to sort an array in O(n log n) time with O(1) auxiliary space. The algorithm first builds a max-heap from the input, then repeatedly extracts the maximum element and places it at the end of the array.
sort-vi-1
Trong Python, bạn có thể sắp xếp một danh sách tại chỗ bằng `list.sort()` hoặc lấy bản sao đã sắp xếp với `sorted(list)`. Cả hai đều nhận đối số `key=` để chỉ định hàm so sánh tùy chỉnh và cờ `reverse=True` để sắp xếp giảm dần. Thuật toán nội bộ là Timsort, độ phức tạp O(n log n) trong trường hợp xấu nhất.
sort-vi-2
Quicksort là thuật toán sắp xếp dựa trên so sánh theo nguyên lý chia để trị: chọn một phần tử trục (pivot) rồi chia mảng thành hai phần nhỏ hơn và lớn hơn trục. Độ phức tạp trung bình là O(n log n), nhưng trường hợp xấu nhất là O(n^2) khi trục luôn là phần tử nhỏ nhất hoặc lớn nhất.
sort-vi-3
Merge sort là thuật toán sắp xếp ổn định, theo nguyên lý chia để trị, với độ phức tạp đảm bảo O(n log n). Nó chia đệ quy đầu vào thành hai nửa, sắp xếp từng nửa, rồi trộn lại thành mảng sắp xếp. Tốn O(n) bộ nhớ phụ, khác với quicksort.
sort-vi-4
Để sắp xếp một danh sách các từ điển trong Python theo một khóa cụ thể, hãy truyền một lambda vào tham số `key`: `sorted(items, key=lambda x: x['age'])`. Cùng mẫu này hoạt động với `list.sort()`. Với nhiều khóa, trả về một tuple từ lambda.
sort-vi-5
Heap sort sử dụng cấu trúc dữ liệu heap nhị phân để sắp xếp mảng với độ phức tạp O(n log n) và O(1) bộ nhớ phụ. Thuật toán đầu tiên xây dựng max-heap từ đầu vào, sau đó liên tục lấy phần tử lớn nhất và đặt vào cuối mảng.
rec-en-1
Recursion is a programming technique where a function calls itself to solve a smaller instance of the same problem. Every recursive function needs a base case to terminate and a recursive case that reduces the problem size.
rec-en-2
The factorial of n can be computed recursively: `def factorial(n): return 1 if n <= 1 else n * factorial(n - 1)`. While elegant, deep recursion in Python can hit the recursion limit; for production code, an iterative loop is usually preferred.
rec-en-3
Tail-call optimization (TCO) lets a compiler reuse the stack frame for a recursive call when the call is the last action in the function. Languages like Scheme and Scala guarantee TCO; Python does not, which is why deep Python recursion overflows the stack.
rec-en-4
Memoization caches the results of expensive recursive calls so they don't get re-computed. Python's `@functools.lru_cache` decorator memoizes a function automatically. Fibonacci is the textbook example — naive recursion is O(2^n), memoized is O(n).
rec-en-5
Tree traversal is a natural fit for recursion: a function visits a node, then recursively visits each child. Pre-order, in-order, and post-order traversals differ only in where the 'visit current node' step happens relative to the recursive calls.
rec-vi-1
Đệ quy là kỹ thuật lập trình trong đó một hàm tự gọi chính nó để giải quyết một phiên bản nhỏ hơn của cùng bài toán. Mọi hàm đệ quy đều cần một trường hợp cơ sở để dừng và một trường hợp đệ quy thu nhỏ kích thước bài toán.
rec-vi-2
Giai thừa của n có thể được tính bằng đệ quy: `def factorial(n): return 1 if n <= 1 else n * factorial(n - 1)`. Tuy đẹp, đệ quy sâu trong Python có thể vượt giới hạn đệ quy; với mã sản phẩm, vòng lặp thường được ưu tiên hơn.
rec-vi-3
Tối ưu hóa lời gọi đuôi (TCO) cho phép trình biên dịch tái sử dụng khung ngăn xếp cho lời gọi đệ quy khi đó là hành động cuối cùng. Scheme và Scala đảm bảo TCO; Python thì không, đó là lý do đệ quy sâu trong Python gây tràn stack.
rec-vi-4
Memoization lưu cache kết quả của các lời gọi đệ quy tốn kém để tránh tính lại. Decorator `@functools.lru_cache` của Python tự động ghi nhớ. Fibonacci là ví dụ kinh điển — đệ quy ngây thơ là O(2^n), có memoize thì O(n).
rec-vi-5
Duyệt cây là ứng dụng tự nhiên của đệ quy: hàm thăm một nút rồi đệ quy thăm từng con. Các thứ tự duyệt tiền tự, trung tự, hậu tự chỉ khác nhau ở vị trí của bước 'thăm nút hiện tại' so với các lời gọi đệ quy.
async-en-1
Async I/O lets a program issue many concurrent I/O operations on a single thread by suspending each one while it waits for the OS to signal readiness. In Python, `asyncio` and the `async`/`await` keywords are the standard tools. The event loop drives all coroutines.
async-en-2
In Rust, `tokio` is the dominant async runtime. You mark functions `async fn`, call them with `.await`, and spawn tasks with `tokio::spawn`. The runtime multiplexes many tasks over a small thread pool — exactly what high-throughput servers need.
async-en-3
Async vs threads: async I/O is best when most of your time is spent waiting on the network or disk (high I/O, low CPU). Threads are better when you need to use multiple CPU cores in parallel for compute-bound work.
async-en-4
A common pitfall in async code is blocking the event loop with a synchronous call. In Rust, wrap CPU-heavy work in `tokio::task::spawn_blocking`. In Python, use `loop.run_in_executor` or `asyncio.to_thread`.
async-en-5
Backpressure is the ability for a consumer to slow down a producer when it can't keep up. Bounded channels (`tokio::sync::mpsc::channel(N)` in Rust) and bounded queues provide backpressure naturally — the producer blocks when the buffer is full.
async-vi-1
Async I/O cho phép một chương trình thực thi nhiều thao tác I/O đồng thời trên một luồng duy nhất bằng cách tạm dừng từng thao tác trong khi chờ OS báo sẵn sàng. Trong Python, `asyncio` và các từ khóa `async`/`await` là công cụ chuẩn. Vòng lặp sự kiện điều khiển tất cả các coroutine.
async-vi-2
Trong Rust, `tokio` là runtime async chủ đạo. Bạn đánh dấu hàm `async fn`, gọi chúng với `.await`, và sinh task bằng `tokio::spawn`. Runtime ghép nhiều task lên một pool luồng nhỏ — đúng thứ máy chủ thông lượng cao cần.
async-vi-3
Async so với thread: async I/O tốt nhất khi phần lớn thời gian bị chặn chờ mạng hoặc đĩa (I/O cao, CPU thấp). Thread tốt hơn khi bạn cần dùng nhiều lõi CPU song song cho công việc nặng tính toán.
async-vi-4
Một lỗi phổ biến trong mã async là chặn vòng lặp sự kiện bằng một lời gọi đồng bộ. Trong Rust, gói công việc nặng CPU vào `tokio::task::spawn_blocking`. Trong Python, dùng `loop.run_in_executor` hoặc `asyncio.to_thread`.
async-vi-5
Backpressure là khả năng người tiêu dùng làm chậm nhà sản xuất khi không theo kịp. Kênh có giới hạn (`tokio::sync::mpsc::channel(N)` trong Rust) và hàng đợi có giới hạn cung cấp backpressure tự nhiên — nhà sản xuất bị chặn khi bộ đệm đầy.
sql-en-1
An INNER JOIN returns only rows where the join condition matches in both tables. If a row in the left table has no match on the right, it's excluded. This is the default JOIN type and the one to use when you want strictly paired rows.
sql-en-2
A LEFT OUTER JOIN returns every row from the left table, plus matching rows from the right. Where there's no match on the right, the right-side columns come back as NULL. Use it to keep all rows from the primary table regardless of the join.
sql-en-3
A FULL OUTER JOIN returns every row from both tables, with NULL filling in the unmatched side. It's the union of LEFT JOIN and RIGHT JOIN. Less common in OLTP, useful for reconciliation queries.
sql-en-4
Use EXPLAIN ANALYZE in PostgreSQL to see the actual execution plan for a JOIN. The planner picks between nested loop, hash join, and merge join based on the size of each side and available indexes. Missing indexes on join keys is the #1 cause of slow queries.
sql-en-5
A CROSS JOIN returns the Cartesian product of two tables — every row on the left paired with every row on the right. Rarely useful directly; mostly appears implicitly when a JOIN condition is forgotten.
sql-vi-1
INNER JOIN chỉ trả về các hàng mà điều kiện join khớp ở cả hai bảng. Nếu một hàng ở bảng bên trái không có khớp bên phải, nó bị loại. Đây là kiểu JOIN mặc định và là lựa chọn khi bạn muốn các cặp hàng được ghép chặt chẽ.
sql-vi-2
LEFT OUTER JOIN trả về mọi hàng từ bảng bên trái, cộng với các hàng khớp ở bên phải. Khi không có khớp ở bên phải, các cột bên phải trả về NULL. Dùng để giữ tất cả hàng từ bảng chính bất kể join.
sql-vi-3
FULL OUTER JOIN trả về mọi hàng từ cả hai bảng, với NULL điền vào bên không khớp. Đây là hợp của LEFT JOIN và RIGHT JOIN. Ít gặp trong OLTP, hữu ích cho các truy vấn đối chiếu.
sql-vi-4
Dùng EXPLAIN ANALYZE trong PostgreSQL để xem kế hoạch thực thi thực tế cho một JOIN. Planner chọn giữa nested loop, hash join và merge join dựa trên kích thước hai bên và các chỉ mục có sẵn. Thiếu chỉ mục trên khóa join là nguyên nhân số 1 của truy vấn chậm.
sql-vi-5
CROSS JOIN trả về tích Đề-các của hai bảng — mỗi hàng bên trái ghép với mỗi hàng bên phải. Hiếm khi dùng trực tiếp; thường xuất hiện ngầm khi điều kiện JOIN bị bỏ sót.
ml-en-1
Supervised learning trains a model on labeled examples — pairs of input and expected output. The model learns a function from inputs to outputs, then predicts labels for new, unseen inputs. Classification and regression are the two main flavors.
ml-en-2
Overfitting happens when a model memorizes the training data rather than learning the underlying pattern. The signal is high training accuracy but low test accuracy. Combat it with more data, regularization, dropout, or simpler model architectures.
ml-en-3
Gradient descent is the workhorse optimization algorithm: compute the gradient of the loss with respect to each parameter, then nudge each parameter a small step in the opposite direction. Variants like Adam adapt the step size per parameter.
ml-en-4
A neural network is a stack of layers, each applying a linear transformation followed by a nonlinear activation (ReLU, GELU). Training adjusts the weights of each linear layer via backpropagation — the chain rule applied across the whole stack.
ml-en-5
Embeddings are dense vector representations of discrete objects (words, sentences, images). Similar inputs map to nearby vectors. They power semantic search, recommendation systems, and retrieval-augmented generation.
ml-vi-1
Học có giám sát huấn luyện mô hình trên các ví dụ có nhãn — cặp đầu vào và đầu ra mong muốn. Mô hình học một hàm từ đầu vào sang đầu ra, rồi dự đoán nhãn cho đầu vào mới chưa thấy. Phân loại và hồi quy là hai kiểu chính.
ml-vi-2
Overfitting xảy ra khi mô hình ghi nhớ dữ liệu huấn luyện thay vì học mẫu nền tảng. Dấu hiệu là độ chính xác cao trên tập huấn luyện nhưng thấp trên tập kiểm tra. Chống lại bằng nhiều dữ liệu hơn, regularization, dropout, hoặc kiến trúc đơn giản hơn.
ml-vi-3
Gradient descent là thuật toán tối ưu chủ đạo: tính gradient của hàm mất mát theo từng tham số, rồi đẩy mỗi tham số một bước nhỏ ngược chiều. Các biến thể như Adam tự điều chỉnh kích thước bước cho từng tham số.
ml-vi-4
Mạng nơ-ron là một chồng các tầng, mỗi tầng áp dụng một biến đổi tuyến tính rồi đến một hàm kích hoạt phi tuyến (ReLU, GELU). Huấn luyện điều chỉnh trọng số của từng tầng tuyến tính qua lan truyền ngược — quy tắc chuỗi áp dụng xuyên suốt chồng.
ml-vi-5
Embedding là biểu diễn vector dày đặc của các đối tượng rời rạc (từ, câu, ảnh). Đầu vào giống nhau ánh xạ tới các vector gần nhau. Chúng hỗ trợ tìm kiếm ngữ nghĩa, hệ gợi ý và sinh có truy xuất tăng cường.
